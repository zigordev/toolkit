# toolkit

The shared base of every zigordev repository: the packages published as `@zigordev/*`, the product template, the pipelines the other repos call, the rules and the handbook. It deploys nothing.

The repo is being built step by step, and each step arrives as its own pull request. This page describes what exists today.

## What it is

| Path                    | What it holds                                                                                                                                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/dev`          | `@zigordev/dev`: the `zigordev` command, the Biome config, the TypeScript bases, the git hooks and the commit rules that every repo shares                                                                                                |
| `packages/config`       | `@zigordev/config`: one function that reads an app's settings from the environment through a Zod schema, and stops the app as it starts when one is missing or wrong                                                                      |
| `packages/otel`         | `@zigordev/otel`: telemetry for a service: traces and metrics through OpenTelemetry, log lines that carry the trace, and the answer of the health route                                                                                   |
| `packages/test`         | `@zigordev/test`: a real PostgreSQL for tests, with one migrated copy per test file, a real Kafka with a signed-in user, and the harness that builds an app for its API tests                                                             |
| `packages/api`          | `@zigordev/api`: the Fastify base of every API: the error format, paging, sign-in checks, a rate limit, the OpenAPI pages, the health route, the database and a clean stop                                                                |
| `packages/events`       | `@zigordev/events`: events between services over Kafka: typed events, the transactional outbox, the consumer with retries and a dead-letter topic, skipped duplicates, trace headers, health and metrics. Private until its first publish |
| `template/`             | The product template: a minimal product that runs on the packages of this checkout. An API with its notes on its own PostgreSQL, a web app, the API's generated client, their images, and the compose files that run them as containers   |
| `.claude/`              | The rules, skills, hooks and permissions that every Claude Code session works under. Every other repo holds a copy of them                                                                                                                |
| `CLAUDE.md`             | What a session needs to know about this repo: where things live, its commands and its own rules                                                                                                                                           |
| `mise.toml`             | The pinned versions of Node.js, pnpm, gitleaks and zizmor                                                                                                                                                                                 |
| `pnpm-workspace.yaml`   | The workspace, the single version of each dependency, and the supply-chain settings                                                                                                                                                       |
| `.github/workflows`     | The pipeline. `check.yml` is the part every repo calls, `release.yml` tags and publishes after a merge, `publish.yml` and `deploy.yml` deliver a product, and `ci.yml` runs the first two for this repo                                   |
| `renovate/default.json` | The Renovate preset that every repo extends: how dependency updates are proposed, and when they merge by themselves                                                                                                                       |
| `docs/`                 | The standard docs, the handbook with its reading order, and the decision records                                                                                                                                                          |

Every pull request runs the pipeline. It runs `pnpm check`, exactly as on a laptop, and three jobs that only GitHub can run: the pull request's title, the dependencies it adds, and a scan of the code. A fifth job builds the images of the product template on an arm64 machine, and holds both apps to the platform contract. One job named `check` passes only when all of them passed, and it is the only check `main` requires.

After a merge, the release works out the next version from the titles that were merged, and publishes every public package under it.

## Why it exists

Every zigordev repo is built with the same tools, set up the same way. Keeping that setup in one versioned place means a repo receives a change as a dependency update, not as a copy made by hand, so the repos cannot drift apart.

The check needs no other repo and no running service. Running the template in containers needs Docker, and one command: [template/README.md](template/README.md) says how.

## Quick start

Install [mise](https://mise.jdx.dev/getting-started.html) and activate it in your shell. Then:

```bash
git clone https://github.com/zigordev/toolkit.git
cd toolkit
mise install
pnpm install
pnpm check
```

`mise install` installs the pinned tools. `pnpm install` installs the dependencies and the git hooks. `pnpm check` runs the full check, and on a clean clone it must end with `check took` and a number of seconds, with no error above it.

| Command                                  | What it does                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `pnpm check`                             | The full check: lint, build, type check, and tests with coverage. It prints how long it took                       |
| `pnpm check:quick`                       | The part of the check that needs no containers. The push hook runs it                                              |
| `pnpm format`                            | Fixes the formatting, the import order and the Markdown problems that have a safe fix                              |
| `pnpm lint`                              | Reports lint and formatting problems without changing a file                                                       |
| `pnpm typecheck`                         | Checks the types                                                                                                   |
| `pnpm test`                              | Runs the tests with coverage                                                                                       |
| `pnpm build`                             | Compiles the packages that are published                                                                           |
| `pnpm --dir template run local:up`       | Starts the shared services and the template in containers, at `http://template.localhost`. It needs Docker running |
| `pnpm --dir template run check:contract` | Builds the template's two images and holds them to the platform contract. It needs Docker running                  |

[packages/dev](packages/dev/README.md) explains what each git hook does, and what the session rules and their guard hook do. [packages/config](packages/config/README.md) explains how an app reads its settings, and [packages/otel](packages/otel/README.md) what a service reports about itself. [template](template/README.md) explains the product template, and how to run it.
